# Specification: Client Feedback & Feature Enhancements

## 1. Overview
This specification consolidates recent client feedback and requested feature enhancements across SacraLink. It establishes clear domain boundaries and technical approaches for:
1. Frictionless Dual-Tier Cashless Donations (Quick Offertory vs. Recorded Acknowledgment).
2. Public Visibility of Super Admin System Announcements for all user roles.
3. Presiding Celebrant / Priest Visibility on Mass schedules, livestreams, and liturgical appointments.
4. Parish Clergy Roster & Availability Status display on Church Detail pages.
5. Priest-Schedule Aware AI Recommender (Suggesting alternative priests in-parish and cross-parish upon conflict).
6. Customizable Sacrament Requirements per Church (with default Death Certificate template for Funerals).

---

## 2. Epics & Detailed Requirements

### Epic 1: Dual-Tier Cashless Donation Experience
- **Problem**: Forcing donors to type 13-digit reference numbers and upload payment screenshots creates high friction, especially for casual livestream givers. However, automated gateway redirects (GCash deep links) require corporate merchant aggregator accounts (PayMongo / Maya Business) that individual chapels lack.
- **Solution**:
  - **Tier A (Default - Quick Love Offering)**: User scans the QR code, clicks a single `"I have sent my offering"` button, and receives a blessing confirmation. Zero typing, zero uploads.
  - **Tier B (Opt-in - Official Acknowledgment / Intention Receipt)**: Donor checks an optional box to input amount (via preset chips `₱50`, `₱100`, `₱500`), reference number, and upload proof.
  - **UX Enhancements**: Include 1-tap "Copy GCash Number" and "Save QR Image" buttons.

### Epic 2: Super Admin System Announcements Public Feed
- **Problem**: Currently, system-wide announcements generated by Super Admins are restricted or not intuitively visible to parishioners on their home feed.
- **Solution**:
  - Expose active system announcements on Parishioner and Church Admin dashboards via the existing `SystemAnnouncementsBanner.tsx`.
  - Provide a dedicated, filterable public Announcements Page where all authenticated users can read official diocese advisories.

### Epic 3: Presiding Priest Visibility Across Liturgies
- **Problem**: Parishioners attending Mass or booking sacraments cannot easily see who the celebrating priest is.
- **Solution**:
  - Display the presiding priest's name and title as a clean badge on Mass schedule cards in `ChurchDetailPage.tsx`.
  - In `LivestreamPlayer.tsx`, display the current presiding priest alongside the broadcast title.
  - Ensure appointment confirmation modals and summary cards include the assigned celebrant.

### Epic 4: Church Clergy Directory & Real-Time Status
- **Problem**: Visitors cannot view the roster of priests assigned to a parish or know their operational availability.
- **Solution**:
  - Add a "Parish Clergy" section/tab in `ChurchDetailPage.tsx`.
  - Display assigned priests (matching `profiles.assigned_church_id` where `is_priest = true` or `user_role = 'priest'`).
  - Render an availability status badge: `Available for Appointment`, `Presiding Mass`, `On Leave / Pastoral Duty`.

### Epic 5: Priest-Aware Smart AI Appointment Recommender
- **Problem**: Current appointment conflict detection only checks general church time slot capacity, ignoring specific priest schedules.
- **Solution**:
  - Allow parishioners to select a preferred priest or view the assigned priest for their chosen sacrament slot.
  - If that priest is unavailable (due to mass, prior booking, or schedule block), the AI activates with two smart recommendations:
    - **Card A (Same Church)**: Recommends an alternative priest available in the same parish for that date/time.
    - **Card B (Nearby Church)**: Recommends an available priest at a neighboring parish within the diocese whose schedule accommodates the user.

### Epic 6: Customizable Sacrament Requirements & Funeral Template
- **Problem**: Sacrament requirements vary between parishes. A rigid global requirement list prevents churches from tailoring their checklists. Additionally, Funeral appointments currently lack the standard Death Certificate requirement.
- **Solution**:
  - **Standard Template**: Seed default `Death Certificate (is_required: true)` for the 'Funeral' service type.
  - **Church Admin Manager**: Implement a management UI for church admins to:
    - Add custom requirements (e.g. Burial Permit, Affidavit).
    - Edit requirement names, descriptions, or toggle `Required` vs `Optional`.
    - Delete requirements not enforced by their parish.
  - **Dynamic Booking Form**: `BookAppointmentPage.tsx` dynamically renders upload dropzones based on the church's customized list.

## 3. Verification & Acceptance Criteria
1. **Type Safety & Build**: All modifications pass `tsc -b` and `vite build` with zero compiler warnings or errors.
2. **E2E Test Coverage**: Extend Playwright E2E suites (`smart-recommender.spec.ts`, `parish-verification.spec.ts`, etc.) to assert priest scheduling and dynamic requirements.
3. **Design System Adherence**: Follow SacraLink clean light-mode tokens (Faith Blue `#2563EB`, Sacred Gold `#F59E0B`, Stone Gray borders `#E2E8F0`).
